# Contributing to ESMotion

1. Keep the package focused on transition state, rendering, interaction,
   diagnostics, and integration boundaries.
2. Keep application business models and navigation policy outside engine
   targets.
3. Do not add a second visual path for the same transition.
4. Add deterministic tests for reversal, cancellation, thresholds, reduced
   motion, lifecycle, geometry, and snapshot budgets.
5. Run `swift test` and build `ESMotionShowcase` for iOS Simulator.
6. Review a real recording before describing a visual or performance change as
   complete.
7. Do not contribute proprietary animation code, private assets, or
   reverse-engineered implementation details.

By contributing, you agree that your contribution is licensed under Apache-2.0.
